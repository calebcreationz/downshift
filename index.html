Downshift

A model a tenth of the price gave the same answers

Downshift audits which model can take over an agent’s decisions on SERV Reasoning, then checks the cost against the bill. These are first results from 60 invented expense claims, so read them as a measurement of one task, not a promise.

60 expense-claim decisions

9 rules. Every answer checked by code. Low reasoning effort, through SERV.

Uses the cost per decision from this task, about 600 input tokens each. Yours will differ.

What the audit found

Luna matched Mini on both test sets for about a tenth of the cost

On the 60 claims above, Luna and Mini both scored 60 out of 60. Luna cost $0.0067 and Mini $0.068. A second set of 40 claims under a 17-rule policy gave the same picture: all four models scored 40 out of 40, and Luna cost $0.0064 against Mini’s $0.058. Nano was cheaper than Mini but missed 6 of the 60.

The raw switch does not switch

SERV’s docs describe a request header that turns the reasoning layer off, so a model can be compared with and without it. On chat completions it made no difference. We sent the same one-line request to GPT-5.4 Nano four ways: no header, then three spellings of the header. Every request reported 197 input tokens. In the Playground, raw mode used 172 input tokens where SERV used 385 for the same prompt, so the layer is visible when it is off.

Because of this, the results here compare models with each other. They do not show what SERV adds over calling a model directly. We reported the header to the OpenServ team and had no answer when this page was written.

Short policies broke the answer format, not the reasoning

With a 9-rule policy in the sweep, models often decided correctly but not in the one word we asked for. Strict parsing scored them like this:

Luna: 20 exact, 14 “APPROVED” or “REJECTED”, 6 wrong decisions
Nano: 4 exact, 10 “APPROVED” or “REJECTED”, 24 began “DECISION” or “RESULT”, 2 wrong decisions
Gemini 3.8 Flash: 10 exact, 30 began “DECISION” or “BASED”

The 60-claim run used a different prompt layout and had no format failures. At 17 rules every model answered in the right format. We did not test the obvious fix, a stricter instruction line, because credits ran out. Any gate built on a model needs a format check and a retry.

The cost estimate was wrong once, and the bill caught it

Downshift estimates cost from reported token counts and listed prices. For Gemini 3.8 Flash we used another Gemini model’s price, so the estimate was about $0.07 where the console billed $0.44 across 283 requests. For Mini, Nano and Luna, the estimates came in 5 to 30 percent under the billed totals ($0.28, $0.16 and $0.06, which also include playground tests and retries). The Gemini figure above is recomputed at its listed $1.00 and $4.50 per million tokens. Downshift treats the bill as the source of truth.

What this does not show

  • It is one invented task with 40 to 100 claims per run and one run per setup. Treat small gaps, like 54 against 60, as hints.
  • Answers are computed by code from the policy, so no one labelled anything, but the policy is simpler than real company rules.
  • There is no raw baseline, so nothing here shows what SERV adds over a direct call.
  • Gemini’s cost at 17 rules is not shown because the token counts were not saved.

Run it yourself

The harness is in this repo. It needs a SERV API key and about $0.20 of credit, and runs in a Colab notebook. harness_sweep.py is the policy-size sweep and harness_60cases.py produced the receipt above. The README has the details.
